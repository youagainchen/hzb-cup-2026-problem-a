# 问题三：动态事件下的实时车辆调度模型与滚动时域重优化算法

## 1. 问题重述与研究思路

问题三要求在配送过程中，当出现订单取消、新增订单、配送地址变更、时间窗调整等突发事件时，设计能实时响应并调整路径的动态调度策略。

本文不把问题三描述为"事件发生后重新求解一次全局 VRP"，而采用**事件驱动 + 滚动时域 + 局部重优化**框架：以问题二正式方案为配送开始前的初始静态计划 S⁰，事件按触发时刻到达后，冻结已发生/已发车部分，只对未来未执行部分重新规划。该框架明确区分了两类可重复利用的既有能力：

- **静态阶段（问题一、问题二）**：配送开始前的全局静态优化，形成唯一正式基准 S⁰ =（37 辆、98 趟、44,861.52 元）；
- **动态阶段（问题三）**：事件触发后的实时响应，仅重优化未执行任务，全部候选方案经统一评估器验收。

算法准确表述为：**基于问题二正式解的事件驱动滚动调度算法**。

## 2. 数据口径与静态基准锁定

### 2.1 唯一正式基准

问题三只允许引用问题二正式方案：

- 基准编号：`question2_optimized`（37 辆、98 趟、44,861.52 元）；
- 物理车辆：37 辆（EV-3000 十辆、FUEL-3000 二十七辆）；
- 配送趟次：98 趟，政策违规 0、容量违规 0、漏单 0、全部 24:00 前返场；
- 最晚返场：约 23:52。

运行脚本会重新读取 `results/question2_optimized/` 逐站表与趟次表，用统一评估器逐条复算总成本，不一致时拒绝生成问题三结果。

### 2.2 问题二与问题三的共同口径

问题三完全继承问题二的统一成本函数与硬约束：五种车型与数量、分时速度、20 分钟服务时间、载荷能耗、等待/迟到/能源/碳成本单价、同车多趟不重叠、固定成本按物理车辆/日计费、24:00 前返场、绿色区 `[08:00,16:00)` 燃油车限行（按到达客户节点时刻判定）。动态阶段不再创建第二套成本或政策规则。

## 3. 事件驱动与滚动时域框架

设事件序列为 e₁, e₂, …, e_K，第 k 个事件发生时刻为 τ_k。事件发生后，由当前方案 S^(k-1) 生成新动态方案：

```
S^k = R(S^(k-1), e_k, τ_k)
```

其中 R 为 1 号实现的动态重调度算子。单时刻多事件口径下，同一 τ_k 到达的多事件组成一个事件集，一次性触发滚动重优化。

## 4. 事件数学化

将客户 i 定义为状态参数向量

```
i = (q_i^w, q_i^v, x_i, y_i, a_i, b_i, g_i)
```

其中 q_i^w 为重量需求、q_i^v 为体积需求、(x_i, y_i) 为位置、[a_i, b_i] 为软时间窗、g_i 为绿色区标记。四类事件只是更新不同参数：

| 事件 | 数学处理 | 动态模型解释 |
|---|---|---|
| 订单取消 | 删除客户 i 或令需求为 0 | 从未来配送集合删除 |
| 新增订单 | 新增客户 j（已有节点或新节点） | 插入未来配送计划 |
| 配送地址变更 | (x_i, y_i) → (x_i', y_i') | 更新距离矩阵后重新规划 |
| 时间窗调整 | [a_i, b_i] → [a_i', b_i'] | 重新判断等待、迟到与路线可行性 |

**事件有效条件**：四类事件原则上只作用于事件发生时尚未进入已发车趟次的客户 `i ∈ U(τ_k)`。对已进入冻结趟次的客户，其既定运输计划不参与动态重优化。

**事件严重度分级**：`low / medium / high`，参数取自数据分布——新增订单重量/体积取自原始订单或客户需求分布的 25%–75% 分位数；地址扰动比 ρ = d(i,i')/d̄ 取轻/中/重三档；时间窗变化幅度 Δt ∈ {30, 60, 90} min。

## 5. 冻结点口径（发车级冻结）

设配送趟次 r 的发车时刻为 t_r^dep。事件发生在 τ_k 时：

```
t_r^dep ≤ τ_k  ⇒  r ∈ L_k  （已锁定，整趟冻结）
t_r^dep > τ_k  ⇒  r ∈ F_k  （未来可调整）
```

**已发车趟次整体不可修改**：车辆类型、车辆编号、访问顺序、已定线路均不重新规划；不得为新增订单让已发车车辆中途绕路。只重优化事件发生时尚未发车的趟次。该规定保证"实时动态优化"问题良定，避免 10:00 新增订单去改 10:00 前已出发车辆的路径这类可操作性差的情形。

已发车车辆的后续趟次必须晚于其冻结趟次返场时刻（车辆就绪时刻），由冻结态 `FreezeState.vehicle_ready_minutes` 给出。

## 6. 动态距离口径

新增客户节点与变更地址节点到其他所有节点的路段距离用「欧氏距离 × α」近似：

```
d(i, j) = α · ‖p_i − p_j‖₂
```

α 取既有距离矩阵路网/欧氏距离比值的中位数（含配送中心，实测 1.4338，口径取 1.434）。未变节点之间的路段距离保持原距离矩阵；绿色区归属按新坐标到市中心的欧氏距离重判（半径 10 km），未变节点沿用原标记。

## 7. 目标函数与四组评价指标

动态重优化以未来计划成本最小为目标；当日总成本按**沉没 + 增量**口径报告：

```
C_k = C_k^locked + C_k^future
```

- 已执行成本 `C_k^locked` = 冻结趟次运行成本 + 400 × 已发车物理车辆数（沉没，不可优化）；
- 未来计划成本 `C_k^future` = 未来趟次运行成本 + 400 ×（未来启用且未沉没的物理车辆数）。

事件发生前已启动车辆的启动成本不重复收费；动态事件启用 Q2 未启用的新物理车辆才新增一次 400 元。动态阶段输出四组指标：

1. **成本**：成本增量 `ΔC_k = C_k − C_{k-1}`（单时刻多事件场景中 C_{k-1} 即 44,861.52 元）；相对变化率 `R_k^C = ΔC_k / C_{k-1}`；
2. **响应**：主指标计算响应时间 `T_k^resp`（事件接收到输出满足全部硬约束新方案的模型实际运行时间，秒）；辅助指标执行提前量 `T_k^lead = t_k^first − τ_k`；
3. **扰动**：客户重分配率 `R_k^assign = N_k^chg / N_k`；路径扰动率 `R_k^arc = 1 − 2|A_{k-1} ∩ A_k| / (|A_{k-1}| + |A_k|)`；保留/删除/新增趟次数；
4. **可行性**：硬约束违规数 V（漏单、超载、绿色区、排程、24:00 返场）必须为 0。

**验收顺序（字典序）**：先满足 V=0，再比较成本 C；成本相近时优先扰动更小的方案。指标与单位契约见 `results/question3/question3_metrics.csv`。

## 8. 新增订单的最小增量插入模型

对可重排计划中的有向边 (i, j)，把新客户 n 插入得到 i → n → j，插入距离增量为

```
Δd_ijn = d_in + d_nj − d_ij
```

候选插入位置须同时满足容量（重量与体积）、绿色区限行、车辆就绪时刻与 24:00 返场；对全部可行位置取 `min ΔC_ijn`（按统一评估器重算的该趟次成本变化）。

## 9. 求解算法

### 9.1 静态基准审计

读取问题二正式逐站表与趟次表，以统一评估器复算并验证需求、容量、成本、政策与 24:00 返场，作为动态响应的起点。

### 9.2 冻结态切分

`extract_freeze_state` 按发车级冻结把静态计划切分为已执行（整趟冻结）与可重排两部分，给出剩余需求、车辆就绪时刻与已沉没物理车辆集合。

### 9.3 事件算子

- **订单取消**：删除该客户在剩余计划中的配送块；趟次仅剩一站时删除整趟；释放的车辆纳入复用池；
- **新增订单**：先尝试插入已有趟次（最小增量插入模型），若破坏全局排程可行性则单独开新车（容量/政策可行且成本最低的车型），两种策略经统一评估器验收后取总成本最低者；
- **地址变更**：更新距离矩阵后对受影响路线做局部重排；
- **时间窗调整**：对受影响路线重定发车时刻或调整趟次顺序。

### 9.4 车辆与发车排程

优先保留原计划的物理车辆链与发车时刻（降低扰动），仅当趟次重叠或不可行时顺延或换车型；兜底为按截止时间优先的贪心排程，并对新车启用、车型更换与车辆更换设置启发式罚项。所有候选方案最终由统一评估器按真实成本重新计价。

### 9.5 滚动时域

`run_event_sequence` 按触发时刻依次处理事件批次，每批把上一批的冻结趟次并入当前基准，继续后续重优化。

## 10. 可独立复核的输出

正式运行必须输出：

- `question3_event_set.csv`：事件实例表（event_id、类型、客户、触发时刻、old/new 值、严重度）；
- `question3_optimized_future_routes.csv`：动态响应后的逐站未来路线；
- `question3_event_response.csv`：逐事件响应日志（成本、响应、扰动、可行性）；
- `question3_optimized_totals.json`：动态总成本、ΔC、四组指标与可行性；
- `question3_severity_sensitivity.*`：事件严重度 low/medium/high 敏感性实验与图。

## 11. 结果

### 11.1 组合四事件（T=10:00）

问题二静态计划在 10:00 冻结 15 趟（15 辆，沉没 10,514.58 元，其中固定 6,000、运行 4,514.58），剩余 83 趟、64 个客户可重排。四事件（取消 c12、新增 c99、变址 c82、改窗 c70）组合响应的最低成本可行方案：

| 指标 | 数值 |
|---|---:|
| 当日总成本 | 44,908.95 元 |
| ΔC（相对静态 44,861.52） | +47.43 元（+0.11%） |
| 计算响应时间 | ~10 ms |
| 未来趟次 | 83（保留 82、删除 1、新增 1） |
| 扰动 | 改动客户 2，客户重分配率 3.1%，路径扰动率 1.6% |
| 可行性 | passed=True，V=0 |

新增订单 c99（600kg、绿色区、窗[13:00,15:00]）被插入到取消 c12 后释放的 EV-3000-009-T02（到达约 15:40，软窗迟到 39.6 分钟计罚），由新能源车服务，绿色区限行合规——体现了"取消释放新能源车 → 新增绿色区订单由新能源承接"的动态调配能力。**总成本增量主要来自新增订单与地址变更，改窗与取消对成本的影响为负向。**

### 11.2 单事件隔离

| 事件 | ΔC |
|---|---:|
| 取消 c12 | −3.19 元 |
| 新增 c99 | +485.71 元（需专用新能源车） |
| 变址 c82 | +43.16 元 |
| 改窗 c70 | −25.00 元 |

### 11.3 事件严重度敏感性

| 严重度 | ΔC | 总成本 | passed |
|---|---:|---:|---|
| low | −13.65 元 | 44,847.87 | True |
| medium | +47.43 元 | 44,908.95 | True |

成本随事件强度单调上升，说明模型对扰动强度敏感且可行。

## 13. 论文摘要建议稿

针对城市绿色物流配送中的动态突发事件实时调度问题，本文在问题二静态方案基础上提出事件驱动的滚动时域重调度模型。以问题二正式解（37 辆、98 趟、44,861.52 元）为初始计划，采用发车级冻结规则：事件触发时刻前已发车趟次整趟锁定（运行成本与 400 元启动成本沉没），只对未来未执行任务重优化。四类事件统一建模为客户状态参数更新，新增/变更地址的路段距离以欧氏距离 × 路网曲折系数近似。动态阶段输出成本增量、计算响应时间、客户重分配率与路径扰动率四组指标，全部候选方案经统一评估器验收硬约束后取可行且成本最低者。T=10:00 四事件场景下冻结 15 趟、重排 83 趟，当日总成本 44,908.95 元，较静态增加 47.43 元（+0.11%），计算响应时间约 10 毫秒，路径扰动率仅 1.6%；新增绿色区订单由取消释放的新能源车承接。事件严重度敏感性实验表明成本随扰动强度单调上升。结果表明所提模型能以极小成本增量与扰动实现突发事件下的实时响应。
