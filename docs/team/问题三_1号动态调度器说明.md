# 问题三：1号动态调度器说明

## 职责范围

本模块只负责动态调度与事件响应，不复制 2 号的事件口径、冻结点判定或动态成本计算。所有候选未来计划统一交给 `src/model/q3_evaluator.py` 的 `evaluate_dynamic` 评分。

## 四类算子

- 订单取消：从未来未发车路线删除取消客户；若路线变为空则删除整趟。
- 新增订单：枚举未来路线的插入位置，先检查容量，再用统一评估器比较增量成本；无法插入时尝试新开可行车型。
- 地址变更：事件后的距离矩阵由 2 号模块更新，调度器对受影响路线尝试反转和单点重排。
- 时间窗调整：对受影响路线使用同一局部重排，并在车辆排程阶段重新枚举发车时刻。

## 滚动时域

事件触发时调用 `extract_freeze_state`，将 `start_minutes < T` 的趟次作为整趟冻结；只有未来趟次进入算子和车辆排程。排程阶段保留冻结车辆的就绪时刻，并对未来任务重新选择车型、物理车辆和发车时刻。

候选路线必须同时满足：需求完整、容量可行、政策违规为 0、车辆趟次不重叠、24:00 前返场。响应时间使用调度器实际运行耗时测量。

## 运行与输出

```powershell
python tools/run_q3_optimized.py
```

输出文件：

- `results/question3_optimized/question3_optimized_future_routes.csv`：事件后的未来路线；
- `results/question3_optimized/question3_event_response.csv`：逐事件成本、响应时间、扰动和可行性；
- `results/question3_optimized/question3_optimized_totals.json`：事件批次汇总与硬约束验收结果。
