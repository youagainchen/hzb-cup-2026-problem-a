# 问题三动态调度：2号模型口径与手算样例

依据《华中杯A题_问题三动态调度推进分工》，本文件为 2 号交付的：事件实例、动态评估接口、冻结点与响应度量口径、手算样例及事件→策略映射。对应代码：

- `src/model/q3_event.py`：事件类型、`Q3Event`/`Q3EventSet`、`apply_events`（事件后问题数据与欧氏×α距离）；
- `src/model/q3_evaluator.py`：`extract_freeze_state`（冻结态）、`evaluate_dynamic`（沉没+增量计费、可行性、四组响应指标）；
- `tools/run_q3_scenario.py`：把 Q2 正式解在 T=10:00 切分并叠加四类事件的演示运行器（含最小未来计划）。

## 1. 锁定基准与推进前提

- Q2 正式解（唯一基准）：37 辆 / 98 趟 / **44,861.52 元** / 政策违规 0 / 容量违规 0 / 漏单 0 / 全部 24:00 前返场。
- 触发时刻 **T = 10:00**，单时刻多事件，一次滚动重优化。
- 冻结点：**发车级冻结**——T 前已发车趟次整趟冻结（运行成本与 400 元固定成本沉没），未发车趟次与未服务需求重排。
- **事件有效条件**：四类事件原则上只作用于未进入已发车趟次的客户 `i ∈ U(T)`。对已冻结趟次内的客户，其既定运输计划不参与重优化，论文以「本文重点研究能够通过调度系统重新决策的未执行订单」披露。
- 新增/变址距离：**欧氏距离 × α**，α = 1.434（既有距离矩阵路网/欧氏距离比值中位数，含配送中心实测 1.4338）。
- 事件严重度：`low / medium / high`；正式场景参数取自数据分布（见 §2）。

## 4. 手算样例 A：订单取消（客户 12）

**前提**：c12 由 EV-3000-009-T02（EV-3000，14:53 发车，晚于 T=10:00，**未冻结**）单趟服务，停靠为 (12, 53)。车辆 EV-3000-009 无冻结趟次，故其 400 元固定成本未沉没，计入未来计划固定成本。

**路线级距离变化**：`0 → 12 → 53 → 0` 取消 c12 后为 `0 → 53 → 0`，距离增量 `Δd = d_{0,53} − (d_{0,12} + d_{12,53})`；再按 Q2 统一评估器逐项重算能源、碳排、时间成本。

**静态该趟可变成本**（summary 中 trip>1 不计固定成本）：**83.80 元**（其中等待成本 27.53）。

**响应 A — 仅删站、保持 14:53 发车**：仅服务 c53，可变成本 **80.62 元**（等待成本升至 51.39）。早到 c53 使其在窗 [17:59,18:52] 前长时间等待——仅删站而不重定发车并非最优。

**响应 B — 删站 + 重定发车至 16:43**：可变成本 **29.53 元**（等待 0、迟到 0）。相对静态节省 83.80 − 29.53 = **54.27 元**。

**口径验证（沉没+增量）**：未来计划固定成本 = 400 ×（未来车辆 37 − 沉没 15）= 8,800 元；当日总成本 = 已执行 10,514.58 + 未来 34,330.62 = **44,845.20 元**；ΔC = −16.32 元（相对变化 −0.04%）。ΔC 为负来自取消，但被变址/改窗造成的等待与路程增加部分抵消。

**重要说明**：本例的最小未来计划只响应了取消（其余趟次保持静态、新增 c99 未插入），评估器据此报出可行性缺口：未完成客户 1（c99，600kg/1.8m³）、排程违规 1（EV-3000-004 因 c82 变址导致趟次重叠）。`passed=False` 只用于验证账目口径，**不是最终可行解**；由 1 号调度器补齐为可行计划后 `passed=True`。

## 5. 手算样例 B：新增订单的最小增量插入（客户 99）

**模型**：对可重排计划中的有向边 `(i,j)`，把新客户 `n` 插入得到 `i → n → j`：

`Δd_{ijn} = d_{in} + d_{nj} − d_{ij}`，`ΔC_{ijn}` = 按统一评估器重算的该趟次成本变化。

**候选位置约束检查**（对每个可行 `(i,j)` 依次验证）：
1. 容量：`Q^w + q_n^w ≤ Q_max^w` 且 `Q^v + q_n^v ≤ Q_max^v`；
2. 绿色区限行：c99 位于绿色区且窗 [13:00,15:00] 落在限行期 `[08:00,16:00)` → 只能插入**新能源**趟次或启用新能源车；
3. 车辆就绪时刻与趟次不重叠；
4. 24:00 前返场。

对全部可行位置取 `min ΔC_{ijn}`。**该插入由 1 号调度器实现；2 号在此只定义插入模型、约束与成本口径。**

## 6. 事件 → 策略映射

| 事件 | 一级策略 | 二级策略 | 兜底 |
|---|---|---|---|
| 订单取消 | 删除该客户配送块；趟次仅剩一站则删整趟 | 邻近路线重新合并 | 未来任务局部重优化 |
| 新增订单 | 最小增量插入（§5） | 跨趟次重新分配 | 启用闲置车辆（新增一次400元） |
| 地址变更 | 更新距离矩阵 | 当前未来线路局部重排 | 跨路线调整 |
| 时间窗调整 | 同路线重排 | 换趟次/换车辆 | 未来任务整体重优化 |

## 7. 四组响应度量（`evaluate_dynamic` 输出）

| 组 | 指标 | 本例最小计划数值 |
|---|---|---|
| 成本 | `C_total`、ΔC、`R^C` | 44,845.20 元；ΔC = −16.32；−0.04% |
| 响应 | `T^resp`（计算耗时，调度器计时）；`T^lead`（执行提前量） | T^lead = 4 分钟（首趟 10:04 发车） |
| 扰动 | 改动客户 1、重分配率 1.56%、路径扰动率 0.79%、保留/删除/新增 82/1/1 | — |
| 可行性 | 漏单、容量、绿色区、排程、24:00 返场 | passed=False（见 §4） |

完整指标与单位契约：`results/question3/question3_metrics.csv`。

**验收顺序（字典序）**：`min(V, C, D)`——先满足 `V=0`，再比较成本 `C`；成本相近时优先扰动 `D` 更小的方案。程序不强求三目标加权，论文以「成本为主目标、扰动为辅助评价」表述。

## 8. 1 号动态调度器接口契约

`evaluate_dynamic(future_routes, freeze_state, evaluator_after, static_total_cost, static_routes)` 返回 `DynamicEvaluation`，其中：

- `future_routes`：`list[Route]`，`start_minutes` 由调度器给定（不早于车辆就绪时刻）；
- 必须覆盖 `freeze_state.remaining_demand`，每车趟次不重叠；
- 政策违规、容量、24:00 返场由评估器统一判定，`passed=True` 为调度器的验收条件；
- 保留趟次建议沿用静态 `route_id`，便于扰动统计。
